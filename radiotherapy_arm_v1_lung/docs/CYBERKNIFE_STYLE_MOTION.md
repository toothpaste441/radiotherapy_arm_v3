# CyberKnife-style multi-viewpoint head targeting (educational demonstration)

## Run

From the `radiotherapy_arm_v1` directory, install dependencies and run:

```powershell
python -m pip install -r requirements.txt
python -m pytest -q tests/test_beam_ik.py tests/test_brain_scene.py tests/test_planning.py
python robot_simulation.py --cyberknife-view
```

Headless: `python robot_simulation.py --cyberknife`.

This mode **does not replace** `--brain-view` or `--plan-view`.

## What moves

- A static simplified patient lies on a table, with a synthetic tumour inside the head.
- The 6R robot moves through seven different *illustrative* noncoplanar viewpoints around the same stationary target.
- From each viewpoint, a tool-local +X **virtual beam direction** is intended to point toward the red brain target. The yellow beam dots trace the **actual** tool axis, not a line artificially snapped onto the tumour.
- NumPy code calculates the joint angles using *position plus tool-axis* inverse kinematics. Unlike the earlier `--brain` mode, this does attempt to control the beam pointing direction.
- RRT-Connect searches for simplified-proxy-clear joint routes between viewpoints; quintic interpolation provides stop-to-stop joint trajectories. A PD controller with MuJoCo gravity/bias compensation executes each trajectory.
- At each node, the arm pauses for 2 seconds and the simulator measures whether it actually reaches the desired tool pose and points its axis toward the tumour.

## Mathematical method

For tool position **p**, beam unit vector **d** (world-frame tool +X), target position **p\*** and target direction **d\***, solve the weighted geometric error

```
e = [p* - p; w (d* - d)]
J = [Jv; w Jd]
Jd[:, i] = omega_i cross d
step = J.T (J J.T + lambda^2 I)^(-1) e
```

with joint-limit clipping and backtracking line search. The unit direction has two independent degrees of freedom; tool rotation around its own beam axis is intentionally unconstrained.

Multiple viewpoints are generated by small ±7° to ±10° offsets relative to the nominal reference beam direction. For each direction, a desired tool point is placed 0.26 m behind the synthetic tumour, and IK is solved to reproduce both position and direction. These are **not clinically optimized nodes**. The prescribed standoff is a visualization parameter, not a radiation treatment specification.

## Outputs

`results/cyberknife_motion/`:

- `multinode_summary.json`: per-viewpoint final geometric errors and simplified collision metrics
- `multinode_samples.csv`: time series of tool errors, beam miss, commanded and actual joint angles, torques
- `multinode_motion.png`: angle and targeting error plots

A viewpoint passes the **illustrative** alignment check only if tool-position error ≤10 mm, beam-ray miss ≤5 mm, and maximum joint speed ≤0.08 rad/s, with the target ahead of the beam and the simplified collision proxy clear. These thresholds are arbitrary classroom demonstration settings, **not clinical tolerances**. If they fail, do not claim that targeting succeeded.

## Known limitations

This is not an actual Accuray CyberKnife controller or treatment planning system. There are **no** radiation dose calculations, imaging, six-axis target-registration calibration, patient movement estimation, collision certification, ray attenuation, treatment optimization, or therapeutic exposure. No radiation is emitted. The existing MuJoCo model uses approximate CAD-derived inertias and torque-limited actuators, which can prevent accurate pose tracking; check the CSV and JSON rather than assuming accuracy from the animation.

The planner approximates robot links as capsules and patient/table geometry as spheres. Neither the actual STL surfaces nor swept-body dynamics and self-collisions are validated. For a clinical system, much more stringent independent physics and safety validation would be mandatory.

## Difference from original brain demo

`--brain-view`: move once to a standoff and hold using **position-only IK**.

`--cyberknife-view`: move through multiple discrete viewpoints with **position-plus-direction IK**, stop, measure aiming error, and continue to the next viewpoint.
